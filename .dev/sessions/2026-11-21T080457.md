A sign-out on the API documentation page ends the session at the identity provider too, so signing in again starts afresh, and nominations are decided like grants, with self-evident names.

- `apps/controller/src/apiDocs/`, `apps/controller/src/identityProvider/`: the page sends the browser to the end-session endpoint the provider's discovery document names, then back to `/api-docs`; a sign-out that only forgets the token leaves the provider's session open, and Swagger UI 5.34.1's redirect page then exchanges the code still held from the earlier sign-in, which Keycloak refuses as `invalid_code`
- `apps/controller/src/apiDocs/`: the sign-out names no ID token, so none appears in an address, and Keycloak asks the person to confirm the sign-out in its place
- `docs/deployment.md`: the page's client lists `/api-docs` as a valid post-logout redirect URI
- `apps/controller/scripts/erd/areas.ts`, `.dev/design/schema-diagrams.md`: every table belongs to a diagram area, as the generator requires, and the diagrams are regenerated with the nomination answers
- `apps/controller/src/administrators/`, `apps/controller/openapi.json`: a nominee accepts or declines through `POST /admin/nominations/{nominationId}/decisions`, the first user lists every nomination and revokes a pending one, and, where the directory is configured, may nominate anyone in the realm
- `apps/controller/src/`, migration `0013`: every path parameter is named for what it identifies, requests send `accept`, `decline` or `grant` while state reads `accepted`, `declined` or `granted`, stored `rejected` and `refused` decisions are rewritten as `declined`, and every audit field naming a person ends in `Subject`
- `docs/deployment.md`: how to appoint the first administrator
