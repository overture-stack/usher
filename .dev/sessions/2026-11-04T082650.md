# 2026-11-04

Covers the work of 2026-11-02 to 2026-11-04.

## Application keys and the controller's configuration

The database is the only list of applications, and an application's id is generated, with a
`display_name` stored trimmed and in NFC. The controller generates each application's key, stores it
encrypted under its key-encryption key, and shows it once; the application reads it as `USHER_KEY`.
The controller's environment holds only the key-encryption key and the PostgreSQL and Valkey
passwords, so registering, issuing or revoking never restarts it, whatever the deployment. Written
into `schema.md` § Applications, `architecture.md` § Controller, the glossary and the key passages
of `decisions.md`, `security-workflow.md`, `security-threat-model.md` and `adapter-integration.md`.

Ruled along the way, each in `schema.md`:

- an exchange the controller cannot verify gets one `401`, its cause only in the log;
- a check value refuses a wrong key-encryption key at start, and a key that fails to decrypt refuses
  its application alone, at start or at a reload;
- at most two live keys per application, every instance reloading them on a wake through Valkey and
  every 30 seconds, and the instance answering a registration or an issue holding the new key first;
- revoking a key ends every push stream opened under it;
- keys are revoked, never deleted, and a key's change record never copies `encrypted_key`.

## Audit events

`audit-events.md` gains rows for the five application events, `channelAssertion.rejection` with its
eight reason codes, `managementToken.refusal` and `managementToken.refusalTally`, and
`migration.run`, each with a note where a cell is not enough. The envelope's `result` now reads
`denied` for a request refused for the actor's authority or its content, and `failed` for a fault in
the controller or its configuration. A refused key revocation records at `warning`. A refused
management credential is recorded by what it cost to send: one event for a token that verifies, a
tally per interval for one that does not, nothing without a credential. Thresholds over the tallies
belong downstream. Five events the controller's suites record still lack rows, logged in
`tech-debt.md`.

## The controller's API and suites

`apps/controller/openapi.json` is the controller's contract, 41 operations, served with Swagger UI
by the mock at `/docs/`. The controller's suites run in the root workspace, outside the root
`pnpm test` until the controller passes them, and specify applications registered in the database
throughout: generated ids, application keys at the exchange, the EGO migration's audiences in its
request, and listed revocation reasons. In progress: recording refused management credentials.

## Comments, modules and test support

Every comment in the bridge and usher-types says what its code is for, how it works when that is
not obvious, and why, never the flow around it, and a comment explaining a guard states the rule it
enforces. Code takes one folder per concept, an index of explicit named exports, and a `types.ts`
owned by the module calling through each interface. A placeholder for a component not yet
installable never enters a commit, and every committed test passes on a clean checkout. The audit
table holds every event the controller's suites record, and a refused Management API request records
its operation's event as denied.
