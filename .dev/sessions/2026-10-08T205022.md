The adapter design gained its readiness rule, its events and its configuration names, and delegated access got a design of its own.

- `.dev/design/adapter-integration.md`: an application reports not ready only while its Bridge is cold, and ready in every mode after, so a quiet revocation channel never takes open data offline and liveness never depends on the Bridge
- `.dev/design/delegated-access.md`, `.dev/design/README.md`: a client acting for a person reaches an ushered application with that person's grants alone, recorded beside the client as actor, and never gains access by doing so; a sign-in token reaching only the application it was issued for is proposed for decision, and a client's own context is stated as outside Usher's reach
- `.dev/design/adapter-integration.md`: each adapter logs denied, permitted and unavailable events per catalogue and read path, with a server-generated request id, a suspended flag and a no-result reason for a configured catalogue missing from the results; every application reads the Bridge's configuration from the same six `USHER_` variables and refuses to start on a missing or malformed one without echoing its value
