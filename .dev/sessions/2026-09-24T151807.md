# 2026-09-24

## The credential-guard hook stopped approving everything it did not block

The hook in `.claude/settings.json` denied credential files and printed an `allow` decision for every
other tool call, which skips the permission prompt. The final `allow` is gone, so a clean call
produces no output and goes through the normal permission flow, while the denies are unchanged.
Tested before and after against clean paths, a push, `.env`, a private key and a kubeconfig.

## AGENTS.md says adapters, and that this project pushes to `main`

The project note names per-app adapters, and the git dispatch line carries the local refinement that
work is committed on top of `main` and pushed there rather than to a feature branch.

## A category change is announced, and bridges drop the tokens naming the resource

Decided in to-discuss.md, where the item is now resolved, and reflected in decisions.md, where "at
once" now holds end to end for a category change. The version bump stays, so a bridge that missed the
announcement corrects itself at its next refresh.

## A session is never defined, and the open items are its lifecycle

A new HIGH item in to-discuss.md defines a session in Usher's sense as a cached Usher token in one
bridge, and tables the events that end or change one: a revoked grant, a category change, a sign-out
through the identity provider's back-channel logout, a suspension, a late announcement, and an upload
in flight. Whether Usher also keeps a view of live sessions stays open.

## The bridge's logic does not depend on Express

Recorded in decisions.md, architecture.md and the roadmap: token exchange, caching, the revocation
channel and dropping tokens live in a framework-independent core, and the Express layer only wires
it in, so another framework's bridge is another thin layer.

## What Usher reuses from Keycloak, each with a fallback

The connector design in admin-model.md now lists every identity-provider feature Usher relies on,
whether it is a standard or Keycloak's own, and what Usher does against a provider that lacks it,
with no fallback that widens access. A decision in decisions.md records the principle. The planned
connector modules now sit under `modules/`, matching the bridge.

## Closed discussion items moved to the decisions they settled

Every resolved item left to-discuss.md. Where decisions.md already carried the resolution the item
went, and where it did not, the resolution was written into the decision it settled: an expiring
grant writes and announces nothing, one anonymous token per application with a nameless notice, the
adapter supplying the field name while the bridge builds the predicate, roles resolving at issuance,
and an audience identifier per deployed instance. The Custodian item was half open, so its open half
stays as a MEDIUM item.

The JWE key decision had no heading of its own and read as part of the `generatedAt` decision; it
has one now.

A category change is announced only to the applications that serve the resource. Announcing it to
every bridge would tell applications about resources they do not serve, which is what the anonymous
item had rejected a resource-keyed notice for, so the fan-out is filtered by audience. The passage
in security-workflow.md that still called a resource-keyed notice unadopted now says what is
decided.
