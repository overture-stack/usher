"Migration" was given one sense per use, qualifying the schema side, since the Management API and the audit catalogue already use the bare word for the EGO data import.

- `.dev/design/glossary.md`: a disambiguation for migration: a schema migration changes the policy store's structure under the schema migration role, and a data migration brings another system's access records in through the Management API; bare, the word means a data migration, except in `schema.md` and the controller's `migrations` module
- `.dev/design/schema.md`, `.dev/roadmap.md`: the migration role is the schema migration role
