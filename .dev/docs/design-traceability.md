# Design traceability

Every section of the design documents that states a rule or a behaviour, and where it stands: built and tested, partly built, built and tested in another repository, built with no test yet, planned, an open question, or context that states no rule. `pnpm check:traceability` fails when a section has no row, a row names a heading that is no longer a section, a link does not resolve, a built or partial row names no test that exists, an external row links no test in another repository, or a partial, untested or planned row links no roadmap item and an open row no item in the roadmap or to-discuss.md.

| Status     | Meaning                                                                        |
| ---------- | ------------------------------------------------------------------------------ |
| `built`    | Built, and tested here                                                         |
| `partial`  | Its main rule built and tested here; the part still to build is in the roadmap |
| `external` | Built and tested in another repository, whose test is linked                   |
| `untested` | Built, with no test yet                                                        |
| `planned`  | Not built; in the roadmap                                                      |
| `open`     | An unsettled question, in the roadmap or to-discuss.md                         |
| `context`  | States no rule                                                                 |

The two planned Management API operations on resource fields, `GET /admin/resource-fields` and `POST /admin/resource-fields`, answer `501`, and no design section states them, so they have no row here. Their purpose is not recorded.

External rows link Arranger tests at commit `fa6a01cd`, which stays reachable once its branch is gone.
